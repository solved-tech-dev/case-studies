# 结果验证

验证针对数值与物理结果，不要求达到某个运行时间。

## 每次应用运行

`tools/run_case.py` 检查进程退出码。`tools/validate.py` 检查应用是否报告线性或非线性发散、输出时间是否完整、必要物理字段是否存在，以及所有保存的节点和单元场是否有限。PanguLU 路径还要求正确的 provider、成功的原生阶段和每个 RHS 的独立原 CSR 残差：有限且不超过 `1e-8`。插件在将结果返回 PETSc 前就对每列 RHS 单独核验；零 RHS 使用绝对残差。

`hex20-heat` 另将全部节点的最终温度与解析表达式 `200*x+100*y+200*z` 比较，相对 L2 门限为 `1e-6`。

## 参考结果对照

对同一案例、同一网格使用 `--solver reference` 生成参考结果，再调用 `tools/validate.py --reference`。程序要求输出时间、坐标和字段集合相同，对完整时间历史上的每个节点场、单元场及全局场逐值比较，接受条件为 `||差值||₂ <= 1e-12 * sqrt(数据项数) + 1e-6 * ||参考值||₂`。绝对 RMS 项使用模型单位，处理物理上为零、计算后仅剩舍入误差的分量。报告保留相对 L2、绝对 L2/RMS 和最大绝对误差，接近零分量的较大相对误差也不会隐藏。

默认 `petsc` 参考解法器适用于小网格。参考对照是独立线性残差以外的补充检查；只有退出码为零、字段有限，还不能证明两种方法的完整物理场一致。报告没有 `reference_field_relative_l2` 字段时，表示尚未执行参考对照。

环形扭转和圆柱壳案例还会检查 `physics.csv` 中全部物理后处理量及其完整时间历史。参考对照采用 `||差值||₂ <= 1e-12 + 1e-6 * ||参考值||₂`，绝对项使用模型本身的单位，以处理理论为零的对称分量；报告同时保留绝对与相对误差。

## 适配器测试

- `tests/test_sparse.cpp`：检查 CSR/CSC 对应关系、显式零、值更新、非法图结构和已知原系统残差，无需 CUDA。
- `tests/test_native.cpp`：使用真实 PanguLU，检查分解与多 RHS 求解、同矩阵分解复用、系数变化重分解、图变化重分析，需要有许可证的 GPU。
- `tests/test_petsc.cpp`：核验 PETSc 原生 `MatSolve`/`MatMatSolve`、因子对象重建后的缓存保留及完整系数更新，需要有许可证的 GPU 和编译好的插件。
- `tools/verify_sources.py`：检查九个上游原始输入/种子网格与 `upstream.lock.json` 一致，并确认中英文文档完整。

原生测试检查实际分析与数值分解调用次数，不凭配置名称或时间缩短推断复用。应用日志也记录分析、数值分解累计次数。

## 验证范围

小网格通过说明这些原生应用入口、物理字段和求解回调在核验的软件环境中正确衔接，不等于重新完成百万阶性能测试。大网格配置保留此前准备的物理模型，新环境实际运行后仍需核对结果。代码包不附带历史性能数据，也不承诺某个耗时、加速比、线程亲和性、NUMA 页分布或性能复现结果。
